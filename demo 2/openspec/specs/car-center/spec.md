# Спецификация системы учета автомобилей автоцентра

## Purpose

Система должна обеспечивать учет автомобилей в автоцентре,
их прием, изменение информации, продажу и формирование отчета
о количестве автомобилей в наличии и количестве проданных автомобилей.

## Requirements

### Requirement: Прием автомобиля

Система SHALL позволять добавить новый автомобиль в учет автоцентра.

#### Scenario: Успешный прием автомобиля

- **WHEN** пользователь передает корректные данные нового автомобиля
- **THEN** система создает новую запись об автомобиле
- **AND** автомобилю присваивается статус `IN_STOCK`
- **AND** фиксируется дата добавления автомобиля

#### Scenario: Некорректные данные автомобиля

- **WHEN** пользователь передает отсутствующую или некорректную обязательную информацию
- **THEN** система отклоняет запрос
- **AND** возвращает информацию об ошибке валидации
- **AND** автомобиль не добавляется в учет

#### Scenario: Повторный VIN

- **WHEN** пользователь пытается добавить автомобиль с уже существующим VIN
- **THEN** система отклоняет операцию
- **AND** существующая запись не изменяется

### Requirement: Получение автомобилей

Система SHALL позволять получать информацию об автомобилях.

#### Scenario: Получение списка автомобилей

- **WHEN** пользователь запрашивает список автомобилей
- **THEN** система возвращает список зарегистрированных автомобилей

#### Scenario: Получение конкретного автомобиля

- **WHEN** пользователь запрашивает автомобиль по идентификатору
- **THEN** система возвращает информацию о найденном автомобиле

#### Scenario: Автомобиль не найден

- **WHEN** пользователь запрашивает несуществующий идентификатор автомобиля
- **THEN** система сообщает, что автомобиль не найден

### Requirement: Редактирование автомобиля

Система SHALL позволять изменять информацию о зарегистрированном автомобиле.

#### Scenario: Успешное редактирование

- **WHEN** пользователь передает корректные новые данные существующего автомобиля
- **THEN** система обновляет информацию об автомобиле
- **AND** идентификатор автомобиля сохраняется

#### Scenario: Редактирование отсутствующего автомобиля

- **WHEN** пользователь пытается изменить автомобиль, которого нет в системе
- **THEN** система сообщает, что автомобиль не найден

### Requirement: Продажа автомобиля

Система SHALL позволять продавать автомобили, находящиеся в наличии.

#### Scenario: Успешная продажа

- **GIVEN** автомобиль имеет статус `IN_STOCK`
- **WHEN** пользователь выполняет операцию продажи
- **THEN** статус автомобиля изменяется на `SOLD`
- **AND** фиксируется дата продажи

#### Scenario: Повторная продажа

- **GIVEN** автомобиль уже имеет статус `SOLD`
- **WHEN** пользователь повторно выполняет операцию продажи
- **THEN** система отклоняет операцию
- **AND** состояние автомобиля не изменяется

#### Scenario: Продажа отсутствующего автомобиля

- **WHEN** пользователь пытается продать автомобиль, которого нет в системе
- **THEN** система сообщает, что автомобиль не найден

### Requirement: Удаление автомобиля

Система SHALL позволять удалять зарегистрированный автомобиль.

#### Scenario: Успешное удаление

- **GIVEN** автомобиль существует в системе
- **WHEN** пользователь выполняет операцию удаления
- **THEN** запись автомобиля удаляется

#### Scenario: Удаление отсутствующего автомобиля

- **WHEN** пользователь пытается удалить несуществующий автомобиль
- **THEN** система сообщает, что автомобиль не найден

### Requirement: Отчет по автомобилям

Система SHALL формировать отчет о количестве автомобилей в наличии и количестве проданных автомобилей.

#### Scenario: Формирование отчета

- **WHEN** пользователь запрашивает отчет
- **THEN** система возвращает количество автомобилей со статусом `IN_STOCK`
- **AND** система возвращает количество автомобилей со статусом `SOLD`
- **AND** система возвращает общее количество автомобилей

#### Scenario: Пустой автоцентр

- **GIVEN** в системе отсутствуют автомобили
- **WHEN** пользователь запрашивает отчет
- **THEN** количество автомобилей в наличии равно `0`
- **AND** количество проданных автомобилей равно `0`
- **AND** общее количество равно `0`

### Requirement: REST API

Система SHALL предоставлять операции предметной области через REST API.

#### Scenario: Работа с API

- **WHEN** пользователь отправляет корректный HTTP-запрос
- **THEN** система выполняет соответствующую операцию
- **AND** возвращает результат операции в формате JSON

### Requirement: Документирование API

Система SHALL предоставлять описание REST API через OpenAPI.

#### Scenario: Просмотр API

- **WHEN** пользователь открывает Swagger UI
- **THEN** система отображает доступные операции API
- **AND** позволяет выполнять запросы к API

### Requirement: Миграции базы данных

Система SHALL использовать миграции для создания и изменения структуры базы данных.

#### Scenario: Первый запуск системы

- **WHEN** приложение запускается с новой базой данных
- **THEN** система выполняет необходимые миграции
- **AND** создает структуру базы данных

#### Scenario: Повторный запуск системы

- **WHEN** приложение запускается повторно
- **THEN** уже выполненные миграции не выполняются повторно
- **AND** структура базы данных остается согласованной

### Requirement: Работа с базой данных

Система SHALL использовать одну предметную таблицу для хранения автомобилей.

#### Scenario: Хранение автомобилей

- **WHEN** автомобиль добавляется в систему
- **THEN** данные сохраняются в таблице автомобилей
- **AND** состояние автомобиля может быть получено при последующем запросе
